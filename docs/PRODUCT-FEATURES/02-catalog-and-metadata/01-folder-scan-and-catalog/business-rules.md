# Folder scan & catalog — business rules

Section 7 of [F-02-01 Folder scan & catalog](README.md), expanded.

| ID | Rule | Why it exists | Defined in |
|---|---|---|---|
| BR-1 | A file is reported as **unchanged** and not re-read when its size, modification time and the metadata version recorded against it all match its catalog entry. | Makes a full re-scan cheap for libraries that mostly did not change, so the user can always choose the safe option. | `apps/desktop-media/electron/db/media-item-metadata.ts` |
| BR-2 | Whenever the app's metadata format changes, every file is re-read on the next scan even if the file itself did not change. | New fields would otherwise stay empty forever for files scanned by an older build. | `apps/desktop-media/electron/db/media-item-metadata.ts` |
| BR-3 | A file whose content fingerprint differs from the one recorded is always re-read, regardless of size and modification time. | Catches files replaced in place, including ones that kept their original timestamps. | `apps/desktop-media/electron/db/media-item-metadata.ts` |
| BR-4 | A file whose metadata cannot be parsed still gets a catalog entry, with the parse error recorded, and is counted as failed. The scan continues. | One corrupt file must never abort a scan or make the file invisible to the app. | `apps/desktop-media/electron/db/media-item-metadata.ts` |
| BR-5 | Images are read with EXIF and XMP support; videos are read through ExifTool. Both paths fill the same catalog fields. | Users do not distinguish photos from videos when asking what date something was taken. | `apps/desktop-media/electron/db/media-item-metadata.ts`, `apps/desktop-media/electron/lib/extract-video-metadata-exiftool.ts` |
| BR-6 | The scan has four steps when GPS place-name detection is enabled and three when it is not, and the step count is fixed for the whole run — it does not depend on whether any file in this particular folder has coordinates. | A progress indicator that renumbers its own steps mid-run reads as a bug. | `apps/desktop-media/electron/ipc/metadata-scan-handlers.ts` |
| BR-7 | Reconciliation of files missing from disk runs only if the preparation step covered every folder in scope. | A cancelled or partial run must never conclude that files are gone when it simply did not look. | `apps/desktop-media/electron/ipc/metadata-scan-handlers.ts` |
| BR-8 | A changes-only scan reconciles each folder against that folder's full disk contents, not against the list of files it decided to read. | Otherwise every file the scan skipped as unchanged would look like it had vanished. | `apps/desktop-media/electron/lib/folder-tree-quick-scan-incremental-metadata.ts` |
| BR-9 | A folder records its scan timestamp only once all of its files have been processed in that run. Folders in scope that contain no media are recorded immediately. | Freshness must mean "fully read", so the folder dashboard cannot claim a partially scanned folder is done. | `apps/desktop-media/electron/ipc/metadata-scan-handlers.ts` |
| BR-10 | Cancelling stops the scan at the next file boundary. Files already processed keep their entries; the remainder are counted as cancelled. | Cancellation should cost the user nothing already achieved. | `apps/desktop-media/electron/ipc/metadata-scan-handlers.ts` |
| BR-11 | A scan that created nothing, updated nothing, failed on nothing, moved nothing, deleted nothing and geocoded nothing removes its own progress card on completion. | Routine no-op scans, especially the automatic ones, should not accumulate cards the user has to dismiss. | `apps/desktop-media/src/renderer/hooks/ipc-progress-binders.ts` |
| BR-12 | The automatic scan on folder selection is skipped when a manual scan is running, when the folder has no direct media but does have subfolders, or when the folder's direct media count reaches the auto-scan limit (default 100). | Protects a deliberate manual job, avoids pointless work on container folders, and keeps opening a big folder from feeling slow. | `apps/desktop-media/electron/ipc/auto-metadata-scan-policy.ts` |
| BR-13 | A manually started scan continues when the user selects a different folder; only automatic scans are affected by changing selection. | The user asked for the manual scan; navigating away is not a request to stop it. | `apps/desktop-media/src/renderer/hooks/ipc-progress-binders.ts`, `apps/desktop-media/electron/ipc/metadata-scan-handlers.ts` |
| BR-14 | Before an AI pipeline processes an image, the app ensures that image has a catalog entry, extracting its metadata first if needed. | Pipelines must work on folders the user has not scanned, without silently attaching results to nothing. | `apps/desktop-media/electron/ipc/folder-utils.ts` |
| BR-15 | When two paths hold identical content, each path gets its own catalog entry; the second entry starts from the first one's AI metadata but is not merged into it. | Both copies must remain browsable and deletable independently, while the second copy inherits work already done. | `apps/desktop-media/electron/db/media-item-metadata.ts` |
| BR-16 | A scan reports, per folder and in total, how many files may need AI pipelines run or re-run — new entries and entries whose AI results were invalidated. | Lets a future prompt tell the user exactly what became stale. Today these counts are recorded but not surfaced. | `apps/desktop-media/electron/ipc/metadata-scan-handlers.ts` |
| BR-17 | A file deleted from disk has its catalog entry marked as deleted rather than erased, and the entry is restored if the file reappears. Entries deleted for longer than 30 days can be permanently removed. | A file that moves between two folders scanned at different times must not lose its ratings, faces and descriptions in the gap. | `apps/desktop-media/electron/db/media-item-reconciliation.ts` |
| BR-18 | Reading a file never writes to it. The only writes to user files come from the separate, off-by-default write-back feature. | The product's core promise is that it is safe to point at the only copy of an archive. | [Embedded metadata write-back](../06-embedded-metadata-write-back.md) |
